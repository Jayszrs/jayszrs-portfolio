# Portfolio UI review, 22 October 2026

Implemented locally and served at http://localhost:3109 using `.next-linkedin-profile`. No commit, push, or deployment was performed. Following the owner's later cancellation, automatic LinkedIn repost synchronization has been removed.

## Result

- Rebuilt the supplied orange lanyard reference as two SVG textile ribbons with cream geometric printing, an orange buckle, a silver snap hook, and a black/white woven brand label. The vectors remain sharp at larger zoom levels and need no texture download or WebGL runtime.
- Both fabric ends stay pinned to the stage ceiling. The lower ends meet the same physical attachment, and the existing rigid grabbed point, release inertia, mobile touch support, reduced-motion controls, and three-second portrait interval remain.
- Changed the canonical Kali mark to a black ground with a white silhouette. Navbar and badge wordmarks use white. Generated matching 192px, 512px, and Apple touch PNGs from the canonical SVG with `scripts/render-brand-icons.cjs`.
- Completed the earlier dark-only direction: near-black ground, charcoal panels, silver outlines, and black/silver controls based on the requested Wealth Club reference. Removed the obsolete theme switcher, theme-setting script, and spare floating-control gap. Browser/PWA chrome is dark too.
- Removed live backdrop blur from navigation and overlays. Navigation contracts using a threshold-triggered transform instead of changing width on every scroll frame. Lanyard/typing/photo work pauses during page scrolling, while offscreen/hidden, and behind dialogs. The rope SVG no longer has a large-area drop-shadow filter.
- LinkedIn is first in the hero links and social tabs. Native profile/activity links work. The owner declined automatic repost synchronization, so the server adapter, polling, API route, credential configuration and disconnected-feed messages were removed.

### Performance measurements

The current production build at normal CPU speed recorded p95 frame intervals of 27.8ms on the first page-scroll sweep, 13.9ms on the subsequent sweep, and 7.1ms inside the education modal. These are local headless-browser samples, not field Web Vitals or a frame-rate guarantee.

Earlier CPU-4x samples were variable: one pre-change run recorded modal p95 62.4ms, an optimized run recorded 13.9ms, and a later repeated run recorded 83.4ms. They do **not** support a reliable percentage speedup claim. The verified implementation improvements are removal of backdrop filters and per-frame width changes, fewer layout reads/writes, and suspension of background animation work. First-time lazy content/image loading can still create long frames under constrained CPU.
